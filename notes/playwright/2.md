## 3. Why should SDETs learn TypeScript?

Let's understand through practical examples.

### Reason 1: Type Safety

JavaScript example:

```
function calculateTotal(price, quantity) {
    return price * quantity;
}

let total = calculateTotal("Laptop", 2);
```

The mistake may only become apparent when the code executes.

TypeScript example:

```
function calculateTotal(
    price: number,
    quantity: number
): number {

    return price * quantity;
}

let total = calculateTotal("Laptop", 2);
```

Compile-time error

TypeScript identifies that `"Laptop"` is not a number.

SDET benefit: Prevent incorrect test data, invalid function arguments and many automation coding mistakes before test execution.

### Reason 2: Interfaces help organize test data

Imagine testing an e-commerce application.

We need to create multiple test users.

```
interface User {
    username: string;
    password: string;
    email: string;
    role: string;
}
```

Create test data:

```
const user1: User = {
    username: "ravi",
    password: "test123",
    email: "ravi@example.com",
    role: "admin"
};

const user2: User = {
    username: "amit",
    password: "test456",
    email: "amit@example.com",
    role: "customer"
};
```

Now all test users follow the same structure.

SDET benefit: Consistent test data, reusable fixtures and fewer data-related mistakes.

### Reason 3: Classes help implement Page Object Model

One of the most important Playwright design patterns is POM – Page Object Model.

Consider a login page.

```
          LOGIN PAGE
              |
      +-------+-------+
      |               |
      v               v
   Username         Password
      |               |
      +-------+-------+
              |
              v
           Login
```

Instead of writing locators repeatedly in every test, create a reusable LoginPage class.

```
import { Page, Locator } from '@playwright/test';

export class LoginPage {

    readonly page: Page;

    readonly username: Locator;
    readonly password: Locator;
    readonly loginButton: Locator;

    constructor(page: Page) {

        this.page = page;

        this.username =
            page.getByLabel('Username');

        this.password =
            page.getByLabel('Password');

        this.loginButton =
            page.getByRole('button', {
                name: 'Login'
            });
    }

    async login(
        username: string,
        password: string
    ): Promise<void> {

        await this.username.fill(username);

        await this.password.fill(password);

        await this.loginButton.click();
    }
}
```

What did we use?

| TypeScript concept | Playwright application  |
| ------------------ | ----------------------- |
| Class              | LoginPage               |
| Constructor        | Initialize page objects |
| Properties         | Store locators          |
| Interface / Types  | Define test data        |
| Methods            | Reusable user actions   |
| Async/Await        | Browser operations      |
| Access modifiers   | Control class members   |

SDET benefit: Reusability, maintainability and separation of test logic from browser interaction.

### Reason 4: Async/Await is essential for browser automation

Browser automation involves asynchronous operations.

For example:

- Opening a page.
- Waiting for an element.
- Clicking a button.
- Submitting a form.
- Receiving an API response.

Playwright APIs are designed around asynchronous operations.

```
import { test, expect } from '@playwright/test';

test('Login test', async ({ page }) => {

    await page.goto('https://example.com/login');

    await page.getByLabel('Username')
        .fill('ravi');

    await page.getByLabel('Password')
        .fill('test123');

    await page.getByRole('button', {
        name: 'Login'
    }).click();

    await expect(page).toHaveURL(/dashboard/);

});
```

Explain the execution:

```
page.goto()
    |
    | await
    v
Page Loaded

fill()
    |
    | await
    v
Input Completed

click()
    |
    | await
    v
Login Submitted

expect()
    |
    v
Verify Expected Result
```

Mentor tip: Don't introduce fixed delays everywhere using `waitForTimeout()`. Prefer Playwright's auto-waiting locators and web-first assertions.

### Reason 5: Generics help build reusable testing utilities

Suppose we want to create a common API response structure.

```
interface ApiResponse<T> {
    success: boolean;
    message: string;
    data: T;
}
```

Define product response:

```
interface Product {
    id: number;
    name: string;
    price: number;
}
```

Use the generic type:

```
const response: ApiResponse<Product> = {
    success: true,
    message: "Product fetched",
    data: {
        id: 101,
        name: "Laptop",
        price: 55000
    }
};
```

SDET benefit: Reusable API testing utilities, strongly typed responses and common test framework components.

## 6. Practical SDET example: Shopping Cart Automation

Let's implement a simple test using TypeScript and Playwright.

```
import { test, expect } from '@playwright/test';

test('Shopping cart experience', async ({ page }) => {

    // Step 1: Open application
    await page.goto('http://localhost:8000/');

    // Step 2: Open Gallery
    await page.getByRole('link', {
        name: 'Gallery'
    }).click();

    // Step 3: Select product
    await page.locator('[id="12"]').click();

    // Step 4: Add to cart
    await page.getByRole('button', {
        name: 'Add to Cart'
    }).click();

    // Step 5: Verify cart
    await expect(
        page.getByText('Shopping Cart')
    ).toBeVisible();

});
```

This is a simple example; the actual locators and expected cart behavior must match the application under test.

Mentor question: What makes this an SDET-oriented solution rather than just a browser script?

Answer: We can gradually introduce reusable page objects, typed test data, fixtures, API setup, assertions, test isolation and CI/CD execution.

## 10. Final mentor message

Student: Sir, should I learn JavaScript first or directly start TypeScript?

Mentor: Understand JavaScript fundamentals first. You don't need to become a JavaScript expert before learning TypeScript, but you should understand variables, functions, objects, arrays, modules, promises and async/await.

Student: And then Playwright?

Mentor: Yes. Learn TypeScript through Playwright projects. Every language concept should solve a real automation engineering problem.

> A manual tester validates software behavior.
>
> An automation tester automates test scenarios.
>
> An SDET engineers reusable, scalable and maintainable quality systems.

Remember: Playwright may automate the browser, but TypeScript helps you engineer the automation framework.

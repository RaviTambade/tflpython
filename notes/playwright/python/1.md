## 1. Why Python for Test Automation?

Imagine you are testing an e-commerce application.

A customer:

1. Opens the website.
2. Searches for a product.
3. Adds it to the cart.
4. Makes payment.
5. Checks the order confirmation.

Can we automate these activities? Yes. Python provides the programming foundation, Playwright provides browser automation, and pytest provides the testing framework. Understand the relationship:

```
             TEST AUTOMATION ENGINEER
                       |
                       v
                Python Language
                       |
             +---------+---------+
             |                   |
             v                   v
          pytest              Playwright
       Test Framework       Browser Automation
             |                   |
             |              +----+----+
             |              |    |    |
             |              v    v    v
             |           Chrome Firefox WebKit
             |                   |
             +---------+---------+
                       |
                       v
                Application Under Test
                       |
                +------+------+
                |             |
                v             v
             Web UI         REST API
```

Mentor explains:

Python is not necessarily the language used to develop the application.

For example:

| Application       | Test automation         |
| ----------------- | ----------------------- |
| ASP.NET Core      | Python + Playwright     |
| Java Spring Boot  | Python + pytest         |
| Node.js / Express | Python + requests       |
| React / Angular   | Python + Playwright     |
| FastAPI           | Python + HTTPX / pytest |

An automation engineer can test applications developed using different technologies.

## 3. Understanding Variables and Data Types

Before automating an application, we need to understand the data being tested. Consider an e-commerce shopping cart.

```
product_name = "Keyboard"
unit_price = 1200
quantity = 2
is_available = True

total = unit_price * quantity

print(product_name)
print(total)

```

Output:

```
Keyboard
2400
```

### Common Python data types

| Data type | Example            | Automation usage         |
| --------- | ------------------ | ------------------------ |
| str       | `"admin"`          | Username, password, URLs |
| int       | `100`              | Product ID, quantity     |
| float     | `10.5`             | Measurements             |
| bool      | `True`             | Login status             |
| None      | `None`             | Missing values           |
| list      | `[101, 102]`       | Multiple test cases      |
| tuple     | `("admin", 1)`     | Fixed test data          |

## 4. Conditional Statements and Loops

Automation testing involves making decisions.

For example:

- If login succeeds, verify the dashboard.
- If login fails, verify the error message.
- If a product is unavailable, verify that it cannot be added to the cart.

### Conditional statements

```
login_status = True

if login_status:
    print("Login successful")
else:
    print("Login failed")


```

### Loops

Suppose we need to test three user roles.

```
roles = ["student", "mentor", "admin"]

for role in roles:
    print(f"Testing role: {role}")


```

Output:

```
Testing role: student
Testing role: mentor
Testing role: admin
```

Mentor analogy:

A loop is like a teacher checking the attendance of every student rather than checking only one student. In automation, loops help us execute repetitive operations over multiple test data records.

## 5. Functions – Reusable Testing Logic

A good automation engineer avoids repeating the same logic everywhere. 
Consider calculating the shopping cart total.

```
from decimal import Decimal

def calculate_total(price: Decimal, quantity: int) -> Decimal:

    if quantity < 0:
        raise ValueError("Quantity cannot be negative")

    return price * quantity


total = calculate_total(Decimal("1200.00"), 2)

print(total)
```

Output:

```
2400.00
```

### Why functions matter in automation

| Function            | Responsibility        |
| ------------------- | --------------------- |
| login()             | Perform login         |
| logout()            | Perform logout        |
| create_user()       | Create test user      |
| get_product()       | Retrieve product      |
| calculate_total()   | Calculate cart amount |
| validate_response() | Validate API response |

Mentor's principle:

One function should ideally perform one well-defined responsibility.

## 6. Classes and Objects – Organizing Test Data

Now imagine testing 100 products.

Instead of maintaining separate variables for every product, we can represent each product as an object.

```
from dataclasses import dataclass
from decimal import Decimal


@dataclass(frozen=True)
class Product:

    product_id: int
    name: str
    price: Decimal
    quantity: int

    def total_value(self) -> Decimal:
        return self.price * self.quantity


product = Product( 101, "Keyboard", Decimal("1200.00"),  2)
print(product.total_value())


```

### Object-oriented thinking

```
                 Product
                    |
          +---------+---------+
          |         |         |
          v         v         v
      product_id   name      price
          |
          v
       quantity

          |
          v
     total_value()
```

Mentor asks:

"Why should we use a class instead of four independent variables?" Because related data and behavior can be organized together. This becomes particularly useful when designing reusable automation frameworks.

## 7. Exception Handling – Making Tests Dependable

What happens when an application does not respond?
What happens when a product ID is invalid?
What happens when an API returns unexpected data?

Python provides exception handling.

```
from decimal import Decimal


def get_product_price(product_id: int):

    if product_id <= 0:
        raise ValueError("Invalid product ID")

    return Decimal("1200.00")

try:

    price = get_product_price(101)
    print(price)

except ValueError as error:

    print(f"Test data error: {error}")
```

Important mentor lesson:

Never catch every exception simply to prevent a test from failing. A failed test should communicate a genuine problem. Hiding exceptions can create false-positive test results.

```

product = Product("Keyboard", Decimal("1200.00"),  2)
print(product.total_value())

```

This is the beginning of building a maintainable automation framework.

## 9. Introduction to pytest and Playwright

Now let us connect Python programming with actual browser automation.

### First Playwright test

Create `tests/test_homepage.py`.

```
def test_homepage(page):
    page.goto("http://127.0.0.1:8000")

    assert "Home" in page.title()
```

Execute:

```
python -m pytest -v
```

Here is what happens:

1. pytest discovers the test function.
2. The Playwright pytest plugin supplies the `page` fixture.
3. Playwright opens a browser page.
4. The application loads.
5. The assertion verifies the page title.

### Understand the execution flow

```
          python -m pytest
                  |
                  v
          pytest Test Runner
                  |
                  v
          Discover test_*.py
                  |
                  v
          Execute test function
                  |
                  v
          Playwright page fixture
                  |
                  v
             Browser
                  |
                  v
          Web Application
                  |
                  v
             Assertion
                  |
          +-------+-------+
          |               |
          v               v
        PASS             FAIL
```

### Synchronous vs asynchronous Python

Playwright supports two programming styles.

| Synchronous API       | Asynchronous API              |
| --------------------- | ----------------------------- |
| Easier starting point | Useful for async applications |
| Sequential execution  | Uses `async` and `await`      |
| `playwright.sync_api` | `playwright.async_api`        |

For our initial pytest lessons, we will use the synchronous API with the managed `page` fixture.

Do not mix synchronous and asynchronous Playwright APIs in the same test.

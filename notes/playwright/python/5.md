# Lesson 5: pytest fixtures and test lifecycle

**Theme:** Reuse setup safely and make cleanup run even when assertions fail.

## 1. What is a pytest fixture?

A fixture prepares a resource for a test and can clean it up afterward. The `pytest-playwright` plugin supplies fixtures such as `page`, `context`, `browser`, `browser_type`, and `playwright`. A fresh page/context per test helps keep cookies and browser storage isolated.

## 2. Fixture scopes and teardown

Pytest supports `function`, `class`, `module`, `package`, and `session` scopes. Use function scope for mutable test data by default. Share expensive resources only when their shared state is understood and safe.

```python
import pytest
from playwright.sync_api import Page


@pytest.fixture
def home_page(page: Page, base_url: str) -> Page:
    page.goto(base_url)
    return page


def test_home_has_navigation(home_page: Page) -> None:
    assert home_page.get_by_role("navigation").is_visible()
```

For teardown, yield the resource and place cleanup after `yield`:

```python
from collections.abc import Iterator

import pytest
from playwright.sync_api import APIRequestContext, Playwright


@pytest.fixture
def api(
    playwright: Playwright, base_url: str
) -> Iterator[APIRequestContext]:
    context = playwright.request.new_context(base_url=base_url)
    yield context
    context.dispose()
```

Pytest runs code after `yield` even if a test assertion fails. For resources requiring multiple cleanup steps, use `try/finally` and make cleanup failures visible.

## 3. Setup hooks and lifecycle choices

Use fixtures for test dependencies and setup/teardown. Use hooks such as `pytest_runtest_makereport` for runner-wide behavior such as attaching a screenshot on failure. Avoid putting ordinary test setup into global hooks; fixtures make dependencies clearer.

The `page` fixture's lifecycle is managed by `pytest-playwright`; do not close
it manually in each test.

## 4. Page-object fixture

`pages/login_page.py`:

```python
from playwright.sync_api import Page


class LoginPage:
    def __init__(self, page: Page) -> None:
        self.page = page

    def open(self, base_url: str) -> None:
        self.page.goto(f"{base_url}/Account/Login")

    def sign_in(self, username: str, password: str) -> None:
        self.page.get_by_label("Username").fill(username)
        self.page.get_by_label("Password").fill(password)
        self.page.get_by_role("button", name="Sign in").click()
```

`tests/conftest.py`:

```python
import pytest
from playwright.sync_api import Page

from pages.login_page import LoginPage


@pytest.fixture
def login_page(page: Page) -> LoginPage:
    return LoginPage(page)
```

Use it in a test:

```python
from playwright.sync_api import expect


def test_login_form_is_ready(login_page, base_url: str) -> None:
    login_page.open(base_url)
    expect(login_page.page.get_by_label("Username")).to_be_editable()
```

## 5. Fixture dependencies and scope rules

Fixtures can depend on other fixtures; pytest constructs them in dependency order and tears them down in reverse order. A broad-scoped fixture cannot depend on a narrower-scoped fixture. Do not put a mutable `page` or user-specific state into a session-scoped fixture.

Keep test accounts, API contexts, database connections, and created records isolated unless sharing is intentional. Use fixture parameters for well-defined variations such as supported browsers or roles.

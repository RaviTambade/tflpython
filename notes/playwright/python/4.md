# Lesson 4: API testing with Playwright for Python

**Theme:** Test service contracts directly, then combine API setup with UI verification where it adds value.

## 1. UI tests and API tests

| Browser test | API test |
|---|---|
| Exercises rendered UI and browser behavior | Exercises HTTP contract |
| Uses locators and navigation | Uses routes, headers, payloads |
| Usually slower | Usually faster |
| Catches user-visible rendering issues | Isolates service status and data behavior |

Use the application's documented test environment and routes. API tests do not replace browser tests for user-facing pages.

## 2. HTTP methods

| Method | Common purpose |
|---|---|
| GET | Read a resource |
| POST | Create a resource or perform an operation |
| PUT | Replace a resource |
| PATCH | Partially update a resource |
| DELETE | Remove a resource |

The API defines the exact behavior, status codes, and response schemas.

## 3. Create an API context fixture

`tests/conftest.py`:

```python
from collections.abc import Iterator
import os

import pytest
from playwright.sync_api import APIRequestContext, Playwright


@pytest.fixture
def api(playwright: Playwright) -> Iterator[APIRequestContext]:
    base_url = os.environ.get("API_BASE_URL")
    if not base_url:
        pytest.fail("Set API_BASE_URL to the test API URL")

    context = playwright.request.new_context(base_url=base_url.rstrip("/"))
    yield context
    context.dispose()
```

Playwright's request context owns its cookies and resources. The fixture disposes it after each test, keeping test state isolated.

## 4. Read and create resources

```python
from playwright.sync_api import APIRequestContext, expect


def test_list_products(api: APIRequestContext) -> None:
    response = api.get("/api/products")

    assert response.status == 200
    products = response.json()
    assert isinstance(products, list)


def test_create_then_read_product(api: APIRequestContext) -> None:
    payload = {"name": "Test Keyboard", "price": 1200, "quantity": 3}
    created = api.post("/api/products", data=payload)

    assert created.status in (200, 201)
    product = created.json()
    product_id = product["id"]
    try:
        assert product["name"] == payload["name"]
        fetched = api.get(f"/api/products/{product_id}")
        assert fetched.status == 200
        assert fetched.json()["name"] == payload["name"]
    finally:
        deleted = api.delete(f"/api/products/{product_id}")
        assert deleted.status in (200, 204)
```

Replace the accepted statuses and response keys with the actual API contract. Clean up created records through the API or a supported test-data mechanism, preferably in a `try/finally` or fixture teardown.

## 5. Update and delete

```python
def test_update_and_delete_product(api: APIRequestContext) -> None:
    created = api.post(
        "/api/products",
        data={"name": "Temporary Product", "price": 10, "quantity": 1},
    )
    assert created.status == 201
    product_id = created.json()["id"]

    try:
        updated = api.put(
            f"/api/products/{product_id}",
            data={"name": "Updated Product", "price": 12, "quantity": 2},
        )
        assert updated.status == 200
        assert updated.json()["name"] == "Updated Product"
    finally:
        deleted = api.delete(f"/api/products/{product_id}")
        assert deleted.status in (200, 204)
```

If cleanup can itself fail, preserve and report that failure rather than silently ignoring it. Use a unique name/identifier to avoid collisions.

## 6. Authentication and negative cases

Test missing credentials, invalid credentials, expired or malformed tokens, and access to protected routes. Assert the API's specified status and response shape. Do not include real tokens in logs or source files.

Playwright's API context can also be used for setup before opening a page. A combined UI/API journey should verify a user-visible result after the API action, not merely that the setup request returned success.

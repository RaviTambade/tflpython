# Mentor Session: Learning TypeScript Step by Step for Node.js Developers

TRANSFLOWER LEARNING · TYPESCRIPT + NODE.JS DEVELOPMENT

Theme: From JavaScript Programming to Type-Safe Backend Development

## 1. First, reset the mindset

Let's start with a classroom conversation.

Mentor: You already know JavaScript. Can you write a Node.js application using JavaScript?

Student: Yes, Sir. We can use JavaScript to create servers, APIs and database applications.

Mentor: Good! Then why do we need TypeScript?

Student: Maybe because TypeScript provides types?

Mentor: Exactly! But let's understand the real problem.

Consider this JavaScript code:

```
function calculateTotal(price, quantity) {
    return price * quantity;
}

let result = calculateTotal(100, 5);

console.log(result);
```

It works perfectly.

But what happens when another developer writes:

```
let result = calculateTotal("Hello", "World");
```

JavaScript does not complain about these arguments before execution. The result may be unexpected.

TypeScript helps identify many such mistakes during development, before running the application.

Mentor's message:

> JavaScript gives us programming flexibility. TypeScript adds a type system that helps us write more predictable and maintainable JavaScript applications.

```
        +-------------------+
                  |

          OPERATING SYSTEM
                  |
                  v
        File System / Network
        Database / HTTP APIs
```

Important concepts:

- TypeScript is a programming language built on JavaScript.
- TypeScript adds static type checking and other development features.
- TypeScript code is normally transformed into JavaScript.
- Node.js executes JavaScript, not TypeScript's type annotations directly in the traditional compilation workflow.

Modern Node.js also has built-in TypeScript type stripping in supported versions, but it does not perform TypeScript type checking. We will initially learn the traditional `tsc` workflow because it makes the compilation process clear.

```

```

This creates a Node.js project and installs TypeScript as a development dependency.

## 6. Configure TypeScript compiler

Open `tsconfig.json`.

For our beginner project, use these settings:

```
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "CommonJS",
    "rootDir": "./src",
    "outDir": "./dist",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true
  }
}
```

Explain the important properties:

| Property        | Responsibility                     |
| --------------- | ---------------------------------- |
| target          | JavaScript version generated       |
| module          | Module system                      |
| rootDir         | TypeScript source directory        |
| outDir          | Compiled JavaScript directory      |
| strict          | Enables strict type checking       |
| esModuleInterop | Improves CommonJS interoperability |

# Part 2 – Learn Basic Data Types

## 7. JavaScript vs TypeScript

JavaScript

```
let message = "Welcome to Transflower";

let count = 100;

let isActive = true;
```

TypeScript

```
let message: string = "Welcome to Transflower";

let count: number = 100;

let isActive: boolean = true;
```

The syntax is:

```
variableName : dataType = value
```

The colon introduces a type annotation.

## 8. Common TypeScript data types

| Data type | Example                       |
| --------- | ----------------------------- |
| string    | `"Ravi"`                      |
| number    | `100`                         |
| boolean   | `true`                        |
| any       | Any value                     |
| unknown   | Value requiring type checking |
| void      | No meaningful return value    |
| null      | `null`                        |
| undefined | `undefined`                   |

Example:

```
let fullname: string = "John Doe";

let age: number = 25;

let isActive: boolean = true;

let salary: number = 45000.50;

let data: any = "Hello";

data = 100;

let response: unknown = "Success";
```

Mentor Tip: Avoid excessive use of `any`. It disables much of the benefit of TypeScript's type checking. Prefer specific types or `unknown` when the type is not yet known.

## 9. Type inference

Do we always need to specify data types?

No!

TypeScript can automatically infer types.

```
let price = 1000;

let productName = "Laptop";

let status = true;
```

TypeScript understands:

```
price       → number
productName → string
status      → boolean
```

But this is invalid:

```
let price = 1000;

price = "One Thousand";
```



Type Error

&#x20;TypeScript identifies that a string cannot be assigned to a variable inferred as a number.



# Part 3 – Arrays and Objects

## 10. Working with Arrays

JavaScript:

```
let numbers = [10, 20, 30, 40];
```

TypeScript:

```
let numbers: number[] = [10, 20, 30, 40];

let names: string[] = [
    "Ravi",
    "Amit",
    "Priya"
];

let prices: Array<number> = [
    100,
    200,
    300
];
```

Practical exercise:

```
let students: string[] = [
    "Amit",
    "Priya",
    "Rahul"
];

students.push("Sneha");

students.forEach((student) => {
    console.log(student);
});
```

## 11. Working with Objects

JavaScript:

```
let product = {
    id: 101,
    name: "Laptop",
    price: 55000,
    isAvailable: true
};
```

TypeScript:

```
let product: {
    id: number;
    name: string;
    price: number;
    isAvailable: boolean;
} = {
    id: 101,
    name: "Laptop",
    price: 55000,
    isAvailable: true
};
```

But writing object types repeatedly is not convenient.

Let's introduce Type Aliases.

## 12. Type Aliases

```
type Product = {
    id: number;
    name: string;
    price: number;
    isAvailable: boolean;
};

let product1: Product = {
    id: 101,
    name: "Laptop",
    price: 55000,
    isAvailable: true
};

let product2: Product = {
    id: 102,
    name: "Keyboard",
    price: 1500,
    isAvailable: true
};
```

Now multiple objects can share the same type definition.

# Part 4 – Functions and Interfaces

## 13. Functions in TypeScript

JavaScript:

```
function add(a, b) {
    return a + b;
}
```

TypeScript:

```
function add(
    a: number,
    b: number
): number {

    return a + b;
}

let result = add(10, 20);

console.log(result);
```

Understand the syntax:

```
function add(a: number, b: number): number
             |          |            |
             |          |            |
          Parameter  Parameter    Return Type
```

### Optional and default parameters

```
function greet(
    name: string,
    message: string = "Welcome"
): string {

    return `${message}, ${name}`;
}

console.log(greet("Ravi"));

console.log(greet("Amit", "Good Morning"));
```

## 14. Interfaces

An interface defines the structure that an object should follow.

```
interface IProduct {
    id: number;
    name: string;
    price: number;
}

let product: IProduct = {
    id: 101,
    name: "Laptop",
    price: 55000
};
```

Interfaces become especially useful when developing enterprise applications.

For example:

```
interface IProductService {
    getAll(): IProduct[];
    getById(id: number): IProduct | undefined;
    add(product: IProduct): void;
}
```

This is similar to the interface-based programming approach used in C# and ASP.NET Core.

# Part 5 – Classes and OOP

## 15. Classes in TypeScript

```
class Employee {

    private id: number;
    public name: string;
    protected salary: number;

    constructor(
        id: number,
        name: string,
        salary: number
    ) {
        this.id = id;
        this.name = name;
        this.salary = salary;
    }

    display(): void {
        console.log(this.id);
        console.log(this.name);
    }
}

let emp = new Employee(
    101,
    "Ravi",
    75000
);

emp.display();
```

Discuss these concepts:

- Class
- Object
- Constructor
- Properties
- Methods
- Access modifiers
- Inheritance
- Encapsulation
- Polymorphism

# Part 6 – Advanced TypeScript

## 16. Union Types

A variable can support more than one type.

```
let id: number | string;

id = 101;

id = "EMP101";
```

Union types are very useful when working with APIs and dynamic data.

## 17. Generics

Generics allow us to write reusable components that work with different data types.

```
function display<T>(value: T): T {

    console.log(value);

    return value;
}

display<number>(100);

display<string>("Welcome");

display<boolean>(true);
```

Think of generics as reusable type parameters.

## 18. Async and Await

Node.js applications frequently communicate with databases and external APIs.

```
async function getMessage(): Promise<string> {

    return "Welcome to Node.js with TypeScript";
}

async function main() {

    let result = await getMessage();

    console.log(result);
}

main();
```

Explain:

```
Async Function
      |
      v
Returns Promise
      |
      v
Await
      |
      v
Wait for Asynchronous Result
      |
      v
Continue Execution
```

## 20. Install Express and development tools

Inside the project folder:

```
npm install express

npm install -D @types/express @types/node tsx
```

For this beginner project, `tsx` will execute TypeScript during development without requiring a separate manual compilation step each time.

Add scripts in `package.json`:

```
{
  "scripts": {
    "dev": "tsx watch src/app.ts",
    "build": "tsc",
    "start": "node dist/app.js"
  }
}
```

Create `src/app.ts`:

```
import express from "express";

const app = express();

app.use(express.json());

app.get("/", (req, res) => {
    res.send("Welcome to Node.js + TypeScript");
});

app.get("/api/products", (req, res) => {

    const products = [
        {
            id: 101,
            name: "Laptop",
            price: 55000
        },
        {
            id: 102,
            name: "Keyboard",
            price: 1500
        }
    ];

    res.json(products);
});

app.listen(3000, () => {

    console.log(
        "Server running at http://localhost:3000"
    );

});
```

Run:

```
npm run dev
```

Test in the browser or Postman:

```
http://localhost:3000/

http://localhost:3000/api/products
```

## 23. Mentor's closing message

Think about your existing C# and ASP.NET Core knowledge.

| C# / ASP.NET Core | TypeScript / Node.js      |
| ----------------- | ------------------------- |
| C#                | TypeScript                |
| .NET Runtime      | Node.js Runtime           |
| NuGet             | npm                       |
| Interface         | Interface                 |
| Class             | Class                     |
| LINQ              | Array methods / libraries |
| ASP.NET Core MVC  | Express.js                |
| Controller        | Controller                |
| Service Layer     | Service Layer             |
| EF Core           | Prisma / TypeORM          |
| MySQL Connector   | mysql2                    |

These are conceptual mappings, not identical implementations.

My recommendation for Transflower students: Don't teach TypeScript as just JavaScript syntax with types. Teach it as a bridge between JavaScript programming and enterprise application architecture.

Start with language fundamentals, then OOP, interfaces, generics, asynchronous programming, Express REST APIs and finally MySQL database connectivity.

> First understand the language. Then understand the runtime. Finally understand the architecture. That's how we become full-stack developers, not just framework users.

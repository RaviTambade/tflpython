## 3. What Is a Web API?

A Web API is an interface that allows one software application to communicate with another application over a network using standard web protocols such as HTTP.

For example:

```
React Application
       |
       | GET /api/policies
       v
Python FastAPI Application
       |
       v
Returns Policy Information
```

The React application does not need to know whether the backend is written in Python, Java, Node.js, or C#. It only needs to understand the API contract.

### Classroom dialogue

Ravi Sir: Suppose our frontend is written in React and our backend is written in Python. Can they communicate?

Student: Yes, Sir, using HTTP requests.

Ravi Sir: Suppose tomorrow we replace Python with Java. Do we necessarily need to rewrite the React application?

Student: No, Sir, provided the API contract remains compatible.

Ravi Sir: Excellent! That is one of the important benefits of APIs: separation between the client and server implementations.

## 4. Now What is REST ?

# REST

## Representational State Transfer

An architectural style for designing network-based software systems.

Ravi Sir: Students, REST is not a programming language. It is not a Python library. It is not a database. REST is an architectural style that provides principles for designing networked applications.

A RESTful API commonly uses:

* Resources identified by URLs.
* Standard HTTP methods.
* Representations such as JSON.
* Stateless client-server communication.
* Standard HTTP response codes.
For our beginner demonstration, we will focus on resources, URLs, HTTP methods, and JSON.

## 6. Explain Endpoint and URL

```
http://localhost:8000/api/policies
```

Let us break it down:

| Part         | Meaning                         |
|--------------|---------------------------------|
| `http://`    | Communication protocol          |
| `localhost`  | Our development machine         |
| `8000`       | Port where the API server listens |
| `/api`       | API route prefix                |
| `/policies`  | Resource collection             |

Ravi Sir: An endpoint is a specific API address through which a client can interact with a resource or operation.

For our application:

```
/api/policies       → Policy collection
/api/policies/1     → Policy with ID 1
/api/policies/2     → Policy with ID 2
```

Ask students:

Ravi Sir: What does `/api/policies/1` represent?

Student: The insurance policy whose ID is 1.

Ravi Sir: Correct. We use the URL to identify the resource, and the HTTP method to communicate what we want to do with it. This is the key idea before introducing CRUD.

## 7. HTTP Methods: The Language of REST APIs

Let us consider managing a library.

| Library Operation       | HTTP Method | Meaning              |
|-------------------------|-------------|----------------------|
| Show all books          | GET         | Retrieve information |
| Add a new book          | POST        | Create a resource    |
| Replace book details    | PUT         | Update a resource    |
| Remove a book           | DELETE      | Delete a resource    |


GET is intended for retrieving data without changing server state. POST commonly creates resources, while PUT replaces a resource representation and is idempotent when implemented according to HTTP semantics.

For this classroom CRUD example, we use PUT to update all editable policy fields.

## 10. Explain HTTP Status Codes Using Insurance Examples

| Status Code | Meaning                                  | TFLInsurance Example                  |
|-------------|------------------------------------------|---------------------------------------|
| `200 OK`    | Request successful                       | Policy retrieved                      |
| `201 Created` | Resource created                       | New policy added                      |
| `204 No Content` | Successful request, no response body | Policy deleted                        |
| `400 Bad Request` | Invalid request                     | Incorrect request data                |
| `404 Not Found` | Resource not found                   | Policy ID does not exist              |
| `422 Unprocessable Content` | Request content failed validation | Invalid premium data             |
| `500 Internal Server Error` | Unexpected server error       | Unhandled application exception      |

## 3. Complete REST API – `main.py`

The following code implements all four CRUD operations in one Python file.

```
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

# ----------------------------------
# 1. Create FastAPI Application
# ----------------------------------

app = FastAPI( title="TFLInsurance API", description="Simple Insurance Policy Management REST API", version="1.0")

# ----------------------------------
# 2. Define Policy Model
# ----------------------------------

class Policy(BaseModel):
    name: str
    description: str
    maturity: str
    premium: float


# ----------------------------------
# 3. In-memory Policy Collection
# ----------------------------------

policies = [
    {
        "id": 1,
        "name": "Jeevan Labh",
        "description": "Life insurance savings plan",
        "maturity": "10 years",
        "premium": 15000.0
    },
    {
        "id": 2,
        "name": "Jeevan Arogya",
        "description": "Health insurance plan",
        "maturity": "5 years",
        "premium": 12000.0
    },
    {
        "id": 3,
        "name": "Jeevan Suraksha",
        "description": "Family protection plan",
        "maturity": "15 years",
        "premium": 20000.0
    }
]

# ----------------------------------
# 4. Helper Function
# ----------------------------------

def find_policy(policy_id: int):
    for policy in policies:
        if policy["id"] == policy_id:
            return policy

    return None


# ----------------------------------
# 5. READ - Get All Policies
# HTTP GET
# ----------------------------------

@app.get("/api/policies")
def get_all_policies():
    return {
        "message": "Policies retrieved successfully",
        "count": len(policies),
        "data": policies
    }


# ----------------------------------
# 6. READ - Get Policy By ID
# HTTP GET
# ----------------------------------

@app.get("/api/policies/{policy_id}")
def get_policy(policy_id: int):

    policy = find_policy(policy_id)

    if policy is None:
        raise HTTPException( status_code=404, detail="Policy not found" )

    return policy


# ----------------------------------
# 7. CREATE - Add New Policy
# HTTP POST
# ----------------------------------

@app.post("/api/policies", status_code=201)
def create_policy(policy: Policy):

    new_id = max((p["id"] for p in policies), default=0) + 1

    new_policy = {
        "id": new_id,
        **policy.model_dump()
    }

    policies.append(new_policy)

    return {
        "message": "Policy created successfully",
        "data": new_policy
    }


# ----------------------------------
# 8. UPDATE - Modify Existing Policy
# HTTP PUT
# ----------------------------------

@app.put("/api/policies/{policy_id}")
def update_policy(policy_id: int, updated_policy: Policy):

    policy = find_policy(policy_id)

    if policy is None:
        raise HTTPException( status_code=404, detail="Policy not found" )

    policy.update(updated_policy.model_dump())

    return {
        "message": "Policy updated successfully",
        "data": policy
    }


# ----------------------------------
# 9. DELETE - Remove Policy
# HTTP DELETE
# ----------------------------------

@app.delete("/api/policies/{policy_id}")
def delete_policy(policy_id: int):

    policy = find_policy(policy_id)

    if policy is None:
        raise HTTPException( status_code=404, detail="Policy not found" )

    policies.remove(policy)

    return {
        "message": "Policy deleted successfully",
        "deleted_policy": policy
    }


# ----------------------------------
# 10. Root Endpoint
# ----------------------------------

@app.get("/")
def home():
    return {
        "application": "TFLInsurance",
        "message": "Welcome to TFLInsurance REST API",
        "docs": "/docs"
    }
```

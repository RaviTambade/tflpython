# 8. Live Coding — Build the Server

Ravi Sir now opens VS Code.

He creates:

```text
server.py
```

And starts with the basic TCP server.

```python
import socket

server = socket.socket(
    socket.AF_INET,
    socket.SOCK_STREAM
)

server.bind(("127.0.0.1", 5000))

server.listen()

print("Insurance server is waiting...")

connection, address = server.accept()

print("Client connected:", address)

data = connection.recv(1024)

print("Received:", data.decode("utf-8"))

connection.send(
    "Policy request received".encode("utf-8")
)

connection.close()
server.close()
```

# 16. Another Important Problem — TCP Is a Stream

Ravi Sir writes:

```python
data = connection.recv(1024)
```

Then asks:

> “Does this guarantee that we received exactly one complete business message?”

Students may say:

> “Yes, Sir?”

Ravi Sir:

> “No.”

This is an important professional-development moment.

TCP gives us a **byte stream**.

It does not understand:

```text
Message 1
Message 2
Message 3
```

as application-level messages.

For example, the sender may send:

```text
HELLO
WORLD
```

but the receiver might observe chunks differently. Therefore the application needs **message framing**. Possible approaches include:

```text
1. Newline-delimited
2. Fixed-length messages
3. Length-prefixed messages
4. Higher-level protocols
```

The source material explicitly highlights that TCP is a continuous byte stream and that message boundaries are an application-level concern.

## 1. What is socket programming?

Socket programming is a technique for enabling two applications to communicate over a network using sockets. A socket is a communication endpoint. It allows an application to send and receive data.

* An insurance server receives requests.
* The client sends a policy inquiry.
* The server processes the request and sends a response.

## 3. What is a socket?

A socket is an abstraction provided by the operating system for network communication.

In Python, we use the built-in `socket` module.

Python

Run

```
import socket
```

A TCP socket is commonly identified by:

```
Protocol: TCP
Address: 127.0.0.1
Port: 5000
```

The two most common socket types are:

TCP socket

SOCK_STREAM

Reliable, ordered, connection-oriented byte-stream communication.

UDP socket

SOCK_DGRAM

Connectionless datagram communication. Delivery, order and duplicate protection are not guaranteed by UDP itself.

In this session, we will focus on TCP socket programming.

# 4. How TCP client-server communication works

The server must start listening before a client can connect.

### TCP connection lifecycle

1. Server creates socket

socket()

2. Server binds address

bind(host, port)

3. Server listens

listen()

4. Client connects

connect(host, port)

5. Server accepts

accept()

6. Exchange data

send() / recv()

7. Close connection

close()

# 5. Python TCP server

Let's create a small insurance server that receives a customer name and responds with a greeting.

Create a file named `server.py`.

Python

Run

```
import socket

HOST = "127.0.0.1"
PORT = 5000

# Create a TCP socket
server_socket = socket.socket(
    socket.AF_INET,
    socket.SOCK_STREAM
)

# Bind the socket to an address and port
server_socket.bind((HOST, PORT))

# Start listening for incoming connections
server_socket.listen(1)

print(f"Insurance server listening on {HOST}:{PORT}")

# Accept one client connection
client_socket, client_address = server_socket.accept()

print("Client connected:", client_address)

# Receive data from the client
data = client_socket.recv(1024)

customer_name = data.decode("utf-8")

print("Customer name:", customer_name)

# Send response to the client
response = f"Hello {customer_name}, welcome to TFL Insurance!"

client_socket.sendall(response.encode("utf-8"))

# Close the client and server sockets
client_socket.close()
server_socket.close()

print("Server stopped")
```

# 9. Important TCP concept: `recv()` does not mean “receive one complete message”

This is a critical production-level lesson.

TCP provides a continuous byte stream, not individual messages.

Suppose the client sends:

```
"POLICY_APPROVED"
```

The server may receive the bytes in one or more pieces. A single `recv(1024)` is not a guarantee that an entire application message has arrived. Therefore, the application must define a message framing protocol.

Common approaches:

* Newline-delimited messages
* Fixed-length messages
* Length-prefixed messages
* A higher-level protocol such as HTTP

For example, newline-delimited communication:

```
POLICY_APPROVED\n
POLICY_REJECTED\n
```

The receiver accumulates bytes until it sees the newline delimiter.

# 10. Multithreaded socket server

The previous server handles only one client. What if 10 customers connect at the same time? We can create a thread for each client.

Python

Run

```
import socket
import threading

HOST = "127.0.0.1"
PORT = 5000


def handle_client(client_socket, client_address):
    print("Connected:", client_address)

    try:
        while True:
            data = client_socket.recv(1024)

            if not data:
                break

            message = data.decode("utf-8")

            print("Received:", message)

            response = f"Server received: {message}"

            client_socket.sendall(
                response.encode("utf-8")
            )

    finally:
        client_socket.close()
        print("Disconnected:", client_address)


server_socket = socket.socket(
    socket.AF_INET,
    socket.SOCK_STREAM
)

server_socket.setsockopt(
    socket.SOL_SOCKET,
    socket.SO_REUSEADDR,
    1
)

server_socket.bind((HOST, PORT))
server_socket.listen()

print(f"Server listening on {HOST}:{PORT}")

try:
    while True:
        client_socket, client_address = server_socket.accept()

        client_thread = threading.Thread(
            target=handle_client,
            args=(client_socket, client_address),
            daemon=True
        )

        client_thread.start()

except KeyboardInterrupt:
    print("\nServer stopped")

finally:
    server_socket.close()
```

### Architecture

```
                 TCP SERVER
                     │
                 accept()
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
       Client 1   Client 2   Client 3
          │          │          │
       Thread 1   Thread 2   Thread 3
          │          │          │
          └──────────┼──────────┘
                     │
                Shared server
```

This connects socket programming with the previous lesson on multithreading.

Note: The server above uses a simple demonstration protocol. A production server should handle framing, timeouts, resource limits, exceptions and graceful shutdown.

# 11. Async socket programming

Python also supports asynchronous sockets through `asyncio`. For a large number of concurrent I/O connections, an event-loop-based design can be useful.

Python

Run

```
import asyncio

HOST = "127.0.0.1"
PORT = 5000


async def handle_client(reader, writer):
    address = writer.get_extra_info("peername")
    print("Connected:", address)

    try:
        while True:
            data = await reader.readline()

            if not data:
                break

            message = data.decode("utf-8").rstrip("\n")

            print("Received:", message)

            response = f"Server received: {message}\n"

            writer.write(response.encode("utf-8"))
            await writer.drain()

    finally:
        writer.close()
        await writer.wait_closed()
        print("Disconnected:", address)


async def main():
    server = await asyncio.start_server(
        handle_client,
        HOST,
        PORT
    )

    print(f"Async server listening on {HOST}:{PORT}")

    async with server:
        await server.serve_forever()


try:
    asyncio.run(main())
except KeyboardInterrupt:
    print("\nServer stopped")
```

# 12. TCP vs UDP

## TCP

Reliable byte stream

* Connection-oriented
* Ordered delivery
* Retransmission handled by TCP
* Flow and congestion control
* No message boundaries

## UDP

Datagrams

* Connectionless
* Preserves datagram boundaries
* No built-in delivery guarantee
* No built-in ordering guarantee
* Application handles reliability if needed

### UDP example

UDP server

Python

Run

```
import socket

server = socket.socket(
    socket.AF_INET,
    socket.SOCK_DGRAM
)

server.bind(("127.0.0.1", 5001))

print("UDP server listening")

data, address = server.recvfrom(1024)

print("Received:", data.decode("utf-8"))

server.sendto(
    b"Hello from UDP server",
    address
)

server.close()
```

# 13. Socket programming and the OSI/TCP-IP model

Socket programming works primarily with the transport layer abstraction.

```
┌─────────────────────────────────────┐
│ Application                         │
│ Insurance app / HTTP / custom data  │
├─────────────────────────────────────┤
│ Transport                           │
│ TCP or UDP                          │
├─────────────────────────────────────┤
│ Internet                            │
│ IP addressing and routing           │
├─────────────────────────────────────┤
│ Link / Network access               │
│ Ethernet / Wi-Fi                    │
└─────────────────────────────────────┘
```

When you use:

Python

Run

```
socket.socket(socket.AF_INET, socket.SOCK_STREAM)
```

you are requesting an IPv4 TCP socket. The operating system manages much of the lower-level networking.

Most Python web developers do not manually implement TCP servers for ordinary REST APIs. They usually use frameworks and servers such as:

4. How concurrency affects network applications
5. How protocols such as HTTP are built on top of TCP or other transports

# 15. Socket programming and HTTP

A typical HTTP request uses a network connection.

```
Browser / API Client
        │
        ▼
    TCP socket
        │
        ▼
    HTTP request
        │
        ▼
    Web server
        │
        ▼
    HTTP response
```

For example:

http

```
GET /policies/101 HTTP/1.1
Host: insurance.example.com
```

HTTP defines the application-level request and response format. TCP provides the byte-stream transport in the traditional HTTP/1.1 and HTTP/2 over TCP arrangement. HTTP/3 uses QUIC over UDP.

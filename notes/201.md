# FastAPI OTP Generation and Verification API

Let's build a simple OTP (One-Time Password) API using Python FastAPI. We will separate the responsibilities into four layers: Router, Controller, Service, and Repository.

Imagine a user registering on the TFLInsurance application. The system generates a six-digit OTP, stores it temporarily, and verifies it when the user submits the code.

## 1. Understand the architecture

Client / Postman

Requests an OTP or submits an OTP

Router — `router.py`

Maps HTTP endpoints to controller functions

Controller — `controller.py`

Accepts input and returns HTTP responses

Service — `service.py`

Generates OTP and applies verification rules

Repository — `repository.py`

Stores, retrieves and deletes OTP records

The repository in this beginner example will store OTPs in memory using a Python dictionary. Later, you can replace it with MySQL or Redis without changing the overall architecture.

## 4. Define request and response models

File: `schemas.py`

Pydantic models validate incoming JSON and define the API response structure.

```
from pydantic import BaseModel, Field


class OTPRequest(BaseModel):
    mobile: str = Field(min_length=10, max_length=15)


class OTPVerifyRequest(BaseModel):
    mobile: str = Field(min_length=10, max_length=15)
    otp: str = Field(pattern=r"^\d{6}$")


class OTPResponse(BaseModel):
    message: str
    otp: str | None = None


class VerifyResponse(BaseModel):
    message: str
    verified: bool
```


## 5. Repository layer — store the OTP

File: `repository.py`

The repository is responsible for storing and retrieving OTP records. We will use a dictionary for this learning exercise.

```
from datetime import datetime
from typing import Optional


class OTPRepository:

    def __init__(self):
        self.otp_store = {}

    def save(self, mobile: str, otp: str, expires_at: datetime):
        self.otp_store[mobile] = {
            "otp": otp,
            "expires_at": expires_at,
            "attempts": 0
        }

    def get(self, mobile: str) -> Optional[dict]:
        return self.otp_store.get(mobile)

    def increment_attempts(self, mobile: str):
        record = self.otp_store.get(mobile)

        if record:
            record["attempts"] += 1

    def delete(self, mobile: str):
        self.otp_store.pop(mobile, None)
```

Mentor's explanation: Think of the repository as a temporary locker. The service decides what to put inside the locker; the repository manages the stored data.

## 6. Service layer — generate and verify OTP

File: `service.py`

This layer contains the business rules: generating a six-digit code, setting a five-minute expiry, checking the submitted code, and limiting verification attempts.

```
import secrets
from datetime import datetime, timedelta, timezone

from repository import OTPRepository


class OTPService:

    def __init__(self, repository: OTPRepository):
        self.repository = repository

    def generate_otp(self, mobile: str) -> str:
        otp = f"{secrets.randbelow(1_000_000):06d}"

        expires_at = datetime.now(timezone.utc) + timedelta(minutes=5)

        self.repository.save(mobile, otp, expires_at)

        return otp

    def verify_otp(self, mobile: str, submitted_otp: str) -> bool:
        record = self.repository.get(mobile)

        if not record:
            return False

        now = datetime.now(timezone.utc)

        # Check OTP expiration
        if now >= record["expires_at"]:
            self.repository.delete(mobile)
            return False

        # Limit verification attempts
        if record["attempts"] >= 5:
            self.repository.delete(mobile)
            return False

        # Verify the submitted OTP securely
        if secrets.compare_digest(record["otp"], submitted_otp):
            self.repository.delete(mobile)
            return True

        # Count incorrect attempts
        self.repository.increment_attempts(mobile)

        return False
```

Important business rules:

- OTP contains exactly six digits, including possible leading zeros.
- OTP expires after five minutes.
- The user gets at most five verification attempts.
- A successfully verified OTP is deleted and cannot be reused.
- An expired OTP is deleted.

## 7. Controller layer — handle requests

File: `controller.py`

The controller receives validated data, calls the service, and creates the response.

```
from fastapi import HTTPException

from schemas import (
    OTPRequest,
    OTPVerifyRequest,
    OTPResponse,
    VerifyResponse
)
from service import OTPService


class OTPController:

    def __init__(self, service: OTPService):
        self.service = service

    def generate(self, request: OTPRequest) -> OTPResponse:
        otp = self.service.generate_otp(request.mobile)

        # Demo only: returning the OTP is NOT safe in production.
        return OTPResponse(
            message="OTP generated successfully",
            otp=otp
        )

    def verify(self, request: OTPVerifyRequest) -> VerifyResponse:
        verified = self.service.verify_otp(
            request.mobile,
            request.otp
        )

        if not verified:
            raise HTTPException(
                status_code=400,
                detail="Invalid, expired, or unavailable OTP"
            )

        return VerifyResponse(
            message="OTP verified successfully",
            verified=True
        )
```

## 8. Router layer — define API endpoints

File: `router.py`

The router exposes HTTP endpoints and delegates the work to the controller.

```
from fastapi import APIRouter

from schemas import (
    OTPRequest,
    OTPVerifyRequest,
    OTPResponse,
    VerifyResponse
)
from controller import OTPController
from service import OTPService
from repository import OTPRepository


router = APIRouter(
    prefix="/api/otp",
    tags=["OTP"]
)


# Dependency initialization
repository = OTPRepository()
service = OTPService(repository)
controller = OTPController(service)


@router.post("/generate", response_model=OTPResponse)
def generate_otp(request: OTPRequest):
    return controller.generate(request)


@router.post("/verify", response_model=VerifyResponse)
def verify_otp(request: OTPVerifyRequest):
    return controller.verify(request)
```

## 13. Mentor's recap

| Layer      | Responsibility            | Example                       |
| ---------- | ------------------------- | ----------------------------- |
| Router     | HTTP routing              | `POST /generate`              |
| Controller | Request/response handling | `generate()`                  |
| Service    | Business rules            | OTP generation and expiry     |
| Repository | Data storage              | `save()`, `get()`, `delete()` |
| Schema     | Input/output validation   | `OTPRequest`                  |

Production note: This is a learning implementation, not a production-ready authentication system. The in-memory dictionary loses data when the process restarts and is not shared across multiple workers. For production, use Redis or a database with atomic attempt limits, rate limiting, and proper access controls. Deliver the OTP through an SMS or email provider; never return it in the API response. Avoid storing plaintext OTPs in persistent storage, and use generic responses where needed to prevent account enumeration.

The key lesson for students: Router handles the route, Controller handles the request, Service owns the business logic, and Repository owns persistence.

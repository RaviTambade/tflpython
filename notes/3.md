## 2. What is a Function?

A **function** is a named block of code designed to perform a specific task. Think of a function like a machine:

```text
              Input
                │
                ▼
       ┌────────────────┐
       │    Function    │
       └────────────────┘
                │
                ▼
              Output
```

For example:

| Machine         | Input          | Output        |
| --------------- | -------------- | ------------- |
| Coffee Machine  | Powder + Water | Coffee        |
| ATM             | Card + PIN     | Cash          |
| Washing Machine | Dirty Clothes  | Clean Clothes |
| Python Function | Arguments      | Result        |

The important idea is:

> **Input → Processing → Output**

## 4. Defining Your First Function

Python uses the `def` keyword to define a function.

```python
def greet():
    print("Welcome to Transflower Learning")
```

But notice something important.

**Defining a function does not execute it.**

We need to **call** it.

```python
greet()
```

Output:

```text
Welcome to Transflower Learning
```

Think about it this way:

```text
def greet()
     ↓
Teach the computer a skill

greet()
     ↓
Ask the computer to use that skill
```

## 5. Function Flow

A function call changes the normal flow of execution.

```text
Program Starts
      │
      ▼
Call greet()
      │
      ▼
Execute greet()
      │
      ▼
Return to Program
```

This simple idea becomes extremely important when applications contain hundreds or thousands of functions.

## 6. Functions with Parameters

Suppose we want to greet different visitors. We could create:

```python
def welcomeRahul():
    print("Welcome Rahul")

def welcomeSneha():
    print("Welcome Sneha")
```

But this creates unnecessary duplication. Instead:

```python
def welcome(name):
    print("Welcome", name)
```

Now the same function can work with different values:

```python
welcome("Rahul")
welcome("Sneha")
welcome("Anita")
```

Output:

```text
Welcome Rahul
Welcome Sneha
Welcome Anita
```

### Mentor's Thinking

Instead of creating:

```text
welcomeRahul()
welcomeSneha()
welcomeAmit()
```

we create:

```text
welcome(name)
```

and provide the changing information as **input**.  **Separate the reusable logic from the changing data.**


## 7. Multiple Parameters

A function can accept more than one parameter.

```python
def student(name, course):
    print(name, "is learning", course)
```

Calling it:

```python
student("Rahul", "Python")
student("Sneha", "Data Science")
```

Output:

```text
Rahul is learning Python
Sneha is learning Data Science
```

Here:

```text
name   → parameter
course → parameter
```

and:

```text
"Rahul"       → argument
"Python"      → argument
```

## 8. Returning Values

Some functions simply perform an action. Others **calculate something and return the result**.

For example:

```python
def add(a, b):
    return a + b

result = add(20, 30)

print(result)
```

Output:

```text
50
```

The flow is:

```text
20 + 30
   ↓
add()
   ↓
50
   ↓
result
```

### Important Difference

```python
print()
```

displays something.

```python
return
```

sends a value back to the caller. That distinction becomes very important when designing reusable software.

## 9. Functions Can Return Values

A function can return many kinds of values.For example:

```python
def square(number):
    return number * number

print(square(8))
```

Output:

```text
64
```

The returned value can also be stored:

```python
result = square(8)

print(result)
```

Or used in another calculation:

```python
total = square(8) + square(5)

print(total)
```

This is how small functions become **building blocks for larger computations**.

## 10. Understanding Variable Scope

Now imagine a classroom. A student's notebook belongs to that student. Another student cannot simply take the notebook and use its variables. Functions have a similar concept called **scope**.

Consider:

```python
def demo():
    message = "Hello"
    print(message)

demo()
```

This works.

But:

```python
print(message)
```

will produce an error because `message` was created inside `demo()`.

```text
Function
┌──────────────────────┐
│ message = "Hello"    │
│                      │
│ print(message)       │
└──────────────────────┘

Outside
    ↓
message is not available
```

This is a **local variable**.

## 11. Global Variables

A variable declared outside functions is called a **global variable**.

```python
college = "Transflower"

def display():
    print(college)

display()
```

Output:

```text
Transflower
```

The function can access the global variable.

###  Local vs Global

| Local Variable                             | Global Variable                            |
| ------------------------------------------ | ------------------------------------------ |
| Created inside a function                  | Created outside functions                  |
| Normally accessible within that function   | Can be accessed from broader program scope |
| Scope is limited                           | Scope is broader                           |
| Helps keep function-specific data isolated | Can introduce wider dependencies           |

### Mentor's Advice

For professional software:  **Prefer passing data through parameters and returning results rather than unnecessarily depending on global variables.** This makes functions easier to understand, test and reuse.


## 12. Function Arguments

Python supports different ways of passing arguments.

### Positional Arguments

Arguments are matched according to their position.

```python
def multiply(a, b):
    print(a * b)

multiply(5, 4)
```

Here:

```text
a → 5
b → 4
```

### Keyword Arguments

Arguments can be specified by parameter name.

```python
def employee(name, department):
    print(name, department)

employee(department="HR", name="Ravi")
```

Notice that the order does not have to match the parameter declaration when using keyword arguments.


### Default Arguments

A function parameter can have a default value.

```python
def greet(name="Student"):
    print("Welcome", name)

greet()
greet("Anita")
```

Output:

```text
Welcome Student
Welcome Anita
```

The default value is used when the caller does not provide an argument.

## 16. 🚀 Project — Text-Based Adventure Game

Now let's combine our learning. We will build a simple adventure game where different parts of the game are implemented as separate functions.

### Problem Statement

The player explores a mysterious world. The player can choose different paths and encounter different events. The objective is not just to make a game. The objective is to understand:  **How a larger problem can be broken into smaller functions.**

### Game Flow

```text
              Start Adventure
                    │
                    ▼
                Choose Path
               /           \
              /             \
          Forest             Cave
            │                 │
        Treasure            Dragon
            │              /      \
         Victory         Fight     Run
                           │         │
                         Victory    Exit
```

## 17. Algorithm

1. Display a welcome message.
2. Ask the player to choose a path.
3. If the player chooses the forest, guide them to the treasure.
4. If the player chooses the cave, introduce the dragon.
5. If the player chooses to fight, determine the outcome.
6. If the player runs, end the game safely.
7. Display the final result.

## 18. Python Implementation

```python
def welcome():
    print("================================")
    print(" Welcome to the Adventure Game ")
    print("================================")


def forest():
    print("\nYou walk through a peaceful forest.")
    print("You discover a hidden treasure chest!")
    print("🎉 Congratulations! You Win!")


def dragon():
    print("\nA giant dragon appears!")

    choice = input("Do you want to fight or run? ").lower()

    if choice == "fight":
        print("You bravely fight the dragon.")
        print("🏆 You defeat the dragon and become a hero!")

    elif choice == "run":
        print("You escape safely.")
        print("Game Over.")

    else:
        print("The dragon is confused by your answer!")
        print("Game Over.")


def start_game():
    welcome()

    print("\nChoose your path:")
    print("1. Forest")
    print("2. Cave")

    option = input("Enter your choice (1 or 2): ")

    if option == "1":
        forest()

    elif option == "2":
        dragon()

    else:
        print("Invalid choice. Game Over.")


start_game()
```

## 19. Understanding the Architecture

Look carefully at the program.

We have separated responsibilities:

```text
start_game()
     │
     ├── welcome()
     │
     ├── forest()
     │
     └── dragon()
             │
             ├── fight
             └── run
```

This is much better than putting the entire game inside one giant block.

Each function has a **clear responsibility**.

## 24. ⭐ Best Practices for Writing Functions

As a beginner, the goal is: **Make the function work.** As a software engineer, the goal becomes: **Make the function understandable, reusable, testable and maintainable.**

### Follow these practices:

**1. Give functions meaningful names**

Prefer:

```python
calculateTotal()
```

over:

```python
doSomething()
```

**2. Keep one function focused on one responsibility**

Instead of:

```text
processEverything()
```

prefer smaller responsibilities:

```text
validateOrder()
calculateTotal()
processPayment()
generateInvoice()
```

**3. Pass data through parameters**

Prefer:

```python
calculateTotal(order)
```

over relying unnecessarily on global state.


**4. Return values when the result may be reused**

Instead of:

```python
def calculateTotal():
    print(500)
```

prefer:

```python
def calculateTotal():
    return 500
```

Now another part of the application can use the result.

**5. Avoid unnecessary duplication**

If the same logic appears in multiple places, ask: **“Should this become a function?”**

## Step 1: Understand the fundamentals

Software testing means checking whether actual behavior matches expected behavior.

For example:

| Input                       | Expected result                |
| --------------------------- | ------------------------------ |
| Valid username and password | Login succeeds                 |
| Invalid password            | Error message appears          |
| Correct assessment ID       | Assessment result is returned  |
| Unknown student ID          | Appropriate not-found response |

Two important terms:

- Test case: A defined scenario with inputs and expected results.
- Assertion: A check that verifies whether the actual result matches the expected result.

## Step 3: Write your first Python program to test

Create a file named `calculator.py`.

```
def add(a, b):
    return a + b


def divide(a, b):
    if b == 0:
        raise ValueError("Cannot divide by zero")

    return a / b
```

This is the application code we want to test. Notice that the division function explicitly handles an invalid input.

Now create a second file named `test_calculator.py`.

```
from calculator import add, divide
import pytest


def test_add_two_numbers():
    assert add(10, 20) == 30


def test_divide_two_numbers():
    assert divide(10, 2) == 5


def test_divide_by_zero():
    with pytest.raises(ValueError):
        divide(10, 0)
```

Your project structure should look like this:

```
python-testing-lab/
│
├── calculator.py
└── test_calculator.py
```

### Understand the test code

- `test_` tells pytest which functions are tests by default.
- `assert` checks the expected result.
- `pytest.raises()` verifies that the expected exception is raised.

For example:

```
assert add(10, 20) == 30
```

This means: “When I add 10 and 20, I expect the result to be 30.”

## Step 4: Execute the tests

Run this command from the project folder:

```
python -m pytest -v
```

Expected output will be similar to:

```
test_calculator.py::test_add_two_numbers PASSED
test_calculator.py::test_divide_two_numbers PASSED
test_calculator.py::test_divide_by_zero PASSED

3 passed
```

&#x20;All three test cases passed.

If an assertion fails, pytest shows the actual and expected values. That evidence helps the developer find the defect.

## Step 5: Test valid and invalid inputs

A good tester does not test only the happy path. Test boundaries and invalid inputs too.

Let's test several addition cases using `pytest.mark.parametrize`.

Add this to `test_calculator.py`:

```
import pytest
from calculator import add


@pytest.mark.parametrize(
    "a, b, expected",
    [
        (2, 3, 5),
        (0, 0, 0),
        (-2, 2, 0),
        (100, 200, 300),
    ],
)
def test_addition_cases(a, b, expected):
    assert add(a, b) == expected

```

Run:

```
python -m pytest -v
```

Pytest runs the same test logic against all four sets of inputs. This is called parameterized testing.

## Step 6: Learn the software testing levels

Unit testing

Test one function or class in isolation.

Example: Is the fee calculation correct?

Integration testing

Test whether components work together.

Example: Does the service correctly read assessment data from the repository?

API testing

Verify HTTP requests, responses, status codes and data.

Example: Does `/api/students/101` return the correct student?

End-to-end testing

Verify a complete user journey.

Example: Log in, open the student dashboard and view assessment results.

A useful order for fast feedback is to start with unit tests, then integration/API tests, and finally browser-based end-to-end tests. Some projects run integration and API tests in different orders depending on their architecture.

## Step 7: Test a FastAPI application

Suppose our student portal exposes a student API. We can test the endpoint without starting a real network server by using FastAPI's `TestClient`.

Install the dependencies:

```
python -m pip install fastapi httpx pytest
```

Create `main.py`:

```
from fastapi import FastAPI, HTTPException

app = FastAPI()

students = {
    101: {"id": 101, "name": "Rahul"},
    102: {"id": 102, "name": "Priya"},
}


@app.get("/api/students/{student_id}")
def get_student(student_id: int):
    student = students.get(student_id)

    if student is None:
        raise HTTPException(
            status_code=404,
            detail="Student not found",
        )

    return student
```

Create `test_api.py`:

```
from fastapi.testclient import TestClient
from main import app

client = TestClient(app)


def test_get_existing_student():
    response = client.get("/api/students/101")

    assert response.status_code == 200
    assert response.json() == {
        "id": 101,
        "name": "Rahul",
    }


def test_get_missing_student():
    response = client.get("/api/students/999")

    assert response.status_code == 404
    assert response.json()["detail"] == "Student not found"
```

Run the tests:

```
python -m pytest -v
```

What have we tested?

- The successful HTTP response returns status code `200`.
- The response body contains the expected student data.
- A missing student produces status code `404` and a meaningful error.

Mentor's lesson: API testing verifies the service contract. It does not, by itself, prove that the browser UI works correctly.

## Step 8: Automate the browser with Playwright and Python

Prerequisite: A running web application or an accessible test website.

Playwright lets Python control a browser, enter text, click buttons and verify what appears on the page.

Install Playwright:

```
python -m pip install pytest-playwright
python -m playwright install
```

Create `test_login.py`:

```
from playwright.sync_api import Page, expect


def test_login_page_loads(page: Page):
    # Open the login page
    page.goto("http://127.0.0.1:8000/login")

    # Verify that the Login heading is visible
    expect(
        page.get_by_role("heading", name="Login")
    ).to_be_visible()

```

This is a browser smoke test: it checks that the login page loads and the expected heading appears. It assumes your application has a `/login` route and a heading named `Login`.

Run it:

```
python -m pytest -v test_login.py
```

Now consider a login form with username and password fields and a Login button. A successful-login test could look like this:

```
from playwright.sync_api import Page, expect


def test_student_login(page: Page):
    # Open the login page
    page.goto("http://127.0.0.1:8000/login")

    # Enter student credentials
    page.get_by_label("Username").fill("student101")
    page.get_by_label("Password").fill("test-password")

    # Click the Login button
    page.get_by_role("button", name="Login").click()

    # Verify successful navigation
    expect(page).to_have_url(
        "http://127.0.0.1:8000/dashboard"
    )

    # Verify that the student dashboard is visible
    expect(
        page.get_by_role(
            "heading",
            name="Student Dashboard"
        )
    ).to_be_visible()
```

The labels, button name and dashboard URL must match your actual application. Use a dedicated test account and avoid real student credentials.

### What does Playwright do?

Playwright browser automation

Web application

Assertions and test report

Unlike unit tests, this test exercises the actual browser and the application's login flow. The application must be running before you execute it.

## Step 9: Build a regression testing habit

Regression testing means rerunning tests after code changes to check that existing functionality still works.

Imagine a developer changes the student login page. We should verify that:

- Valid login still works.
- Invalid login still shows an error.
- The dashboard still opens.
- Assessment results still load.

Run all your tests together:

```
python -m pytest -v
```

Generate an HTML test report:

```
python -m pip install pytest-html
python -m pytest --html=report.html --self-contained-html
```

The report helps the team review passed tests, failures and test evidence.

## Step 10: Integrate testing into CI/CD

A typical automated workflow looks like this:

Developer commits code to Git

CI pipeline installs dependencies

Run pytest unit and API tests

Run Playwright browser tests

Publish results and report failures

Tools you may encounter include GitHub Actions, GitLab CI, Jenkins and Azure Pipelines. A production pipeline may also include security, performance and deployment checks.

## Final mentor takeaway

Software testing is not simply finding bugs. It is about building confidence in software behavior.

- Python gives you the programming language.
- pytest helps you verify functions and business rules.
- FastAPI TestClient helps you test API behavior.
- Playwright helps you automate browser interactions.
- CI/CD helps you repeat these checks whenever code changes.

Start small. Write one function, create one test, run it, observe the result, and improve it. Then expand from unit testing to API testing and finally browser automation.

Your first milestone: Run the calculator tests successfully. Once you understand `assert`, expected results and failure reports, the rest of the testing journey becomes much easier.

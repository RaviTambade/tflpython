# 7. 🧬 Inheritance

# 8. 🔧 Special / Dunder Methods

Python provides special methods whose names generally begin and end with `__`.

Examples:

```python
__init__
__str__
__new__
```

These are often called **dunder methods**.



## `__init__`

Used for object initialization.

```python
class Customer:

    def __init__(self, name):
        self.name = name
```

```python
customer = Customer("Ravi")
```



## `__str__`

Controls the human-readable string representation.

```python
class Customer:

    def __init__(self, name):
        self.name = name

    def __str__(self):
        return f"Customer: {self.name}"
```

Now:

```python
customer = Customer("Ravi")

print(customer)
```

Output:

```text
Customer: Ravi
```



## `__new__`

`__new__` is involved in **creating the object**, while `__init__` initializes it.

Conceptually:

```text
Class()
  │
  ↓
__new__()
  │
  ↓
Object created
  │
  ↓
__init__()
  │
  ↓
Object initialized
```

This distinction becomes particularly interesting when learning patterns such as **Singleton**.

# 9. ➕ Operator Overloading

Python allows operators to work with user-defined objects through special methods.

Suppose:

```python
class Money:

    def __init__(self, amount):
        self.amount = amount
```

We want:

```python
m1 + m2
```

to work.

Implement:

```python
class Money:

    def __init__(self, amount):
        self.amount = amount

    def __add__(self, other):
        return Money(self.amount + other.amount)
```

Now:

```python
m1 = Money(100)
m2 = Money(200)

m3 = m1 + m2

print(m3.amount)
```

Output:

```text
300
```

### Mentor Question

**Student:** Sir, `+` is normally for numbers. How did it understand `Money`?

**Ravi Sir:**

Because Python translates:

```python
m1 + m2
```

conceptually into:

```python
m1.__add__(m2)
```

That is the power of **operator overloading**.


# 10. 🚨 Exception Handling

Real applications don't always execute successfully.

Example:

```python
premium = float(input("Enter premium: "))
```

What if user enters:

```text
abc
```

The application can fail.

Therefore we use:

```text
try
except
finally
```

Example:

```python
try:

    premium = float(input("Enter premium: "))

    if premium <= 0:
        raise ValueError("Premium must be greater than zero.")

    print("Premium accepted:", premium)

except ValueError as ex:

    print("Invalid premium:", ex)

finally:

    print("Processing completed.")
```

# 11. 🧑‍💻 Custom Exceptions

Sometimes built-in exceptions don't describe our business problem clearly.

For example:

```python
class PolicyException(Exception):
    pass
```

Now:

```python
def issue_policy(age):

    if age < 18:
        raise PolicyException(
            "Customer must be at least 18 years old."
        )

    return "Policy issued"
```

Usage:

```python
try:

    print(issue_policy(15))

except PolicyException as ex:

    print("Policy Error:", ex)
```

### Mentor Principle

> **Technical errors and business errors are not always the same thing.**

For example:

```text
ValueError
        ↓
Technical validation

PolicyException
        ↓
Business rule violation
```

# 13. 🧵 Multitasking and Multithreading

Now application development moves beyond simple sequential execution.

A program can have multiple paths of execution.

```text
Process
   │
   ├── Primary Thread
   │
   ├── Secondary Thread
   │
   └── Secondary Thread
```

A **thread** can be understood as a path of execution.

For example:

```text
Application
      │
      ├── Thread 1 → Process request
      │
      ├── Thread 2 → Read file
      │
      └── Thread 3 → Background work
```

The operating system/runtime coordinates execution of threads and CPU resources.

# 16. 🧠 Stack and Heap

This is one of the most important mental models for developers.

Conceptually:

```text
Process Memory
│
├── Stack
│
└── Heap
```

## Stack

A thread maintains a stack used for execution-related information such as:

* function call frames
* local variables
* return information

Example:

```python
def calculate():
    premium = 10000
    return premium
```

When the function executes, a call frame is associated with the thread's execution stack.

# 18. ♻️ Garbage Collection

Now comes an important question.

**Student:** Sir, who cleans objects that we no longer need?

In languages/runtimes with automatic memory management, a **garbage collector** can reclaim memory occupied by objects that are no longer reachable.

Conceptually:

```text
Application
    │
    ↓
Create Object
    │
    ↓
Object used
    │
    ↓
Reference removed
    │
    ↓
Object becomes unreachable
    │
    ↓
Garbage Collector
    │
    ↓
Memory Reclaimed
```

# 19. 🗑️ What Is Garbage?

Suppose:

```python
customer = Customer("Ravi")
```

There is a reference:

```text
customer
   │
   ↓
Customer Object
```

Later:

```python
customer = None
```

If no other references to that object remain, the object may become unreachable.

Conceptually:

```text
Stack/reference
     │
     X
     │
     ↓

Heap
[Customer Object]

No reachable reference
        ↓
Potential garbage
```

### Important

Don't think:

> “Python immediately destroys the object when I write `None`.”

A better mental model is:

> **The object becomes unreachable; the runtime's memory-management mechanism determines when and how its memory is reclaimed.**

# 21. 💾 Memory Fragmentation

Imagine a room.

Initially:

```text
┌──────────────────────────────┐
│ A │ B │ C │ D │ E │ F │ G  │
└──────────────────────────────┘
```

Now objects are removed:

```text
┌──────────────────────────────┐
│ A │   │ C │   │ E │   │ G  │
└──────────────────────────────┘
```

Free space exists, but it is scattered.

This idea is called **fragmentation**.

Conceptually:

```text
USED | FREE | USED | FREE | USED
```

The memory manager may need mechanisms to manage such fragmented space.


# 22. 🧩 Defragmentation — Be Careful With the Analogy

A useful real-world analogy is a disk.

Windows provides tools for disk optimization/defragmentation for applicable storage systems.

But don't directly equate:

```text
Disk defragmentation
```

with

```text
Python garbage collection
```

They are different mechanisms.

### Remember

```text
Disk management
        ≠
Application heap management
        ≠
Garbage collection
```

They solve different problems.


# 23. 🧵 Primary Thread and Secondary Threads

A process may execute using one or more threads.

Conceptually:

```text
Application Process
       │
       ├── Primary Thread
       │
       ├── Worker Thread
       │
       └── Worker Thread
```

The primary thread begins execution of the application.

In Python, execution commonly begins with the module's top-level code.

For example:

```python
print("Application started")
```

is executed when the module is run.

A common convention is:

```python
if __name__ == "__main__":
    main()
```

This gives us a clear application entry point.

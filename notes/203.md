# FastAPI – Authentication Module using Dependency Injection

Let's build a Python FastAPI application with a clean, modular structure for User Registration and Login.

We will separate responsibilities into:

1. `main.py` – Application entry point.
2. `router.py` – Defines HTTP endpoints.
3. `controller.py` – Handles authentication requests.
4. `service.py` – Implements authentication business logic.
5. `repository.py` – Handles user data access.
6. `database.py` – Database connection.
7. `schemas.py` – Request and response models.
8. `dependencies.py` – Dependency Injection configuration.

We will use FastAPI's built-in `Depends()` mechanism.

## 1. Understand the architecture

Think of a bank application.

- Router is the reception desk.
- Controller understands the customer's request.
- Service implements banking rules.
- Repository communicates with the database.
- Dependency Injection provides required objects.

## 6. Create repository.py

Repository is responsible for data persistence.

For the initial lab, we use an in-memory dictionary. Later, replace this with MySQL.

```
from dataclasses import dataclass@dataclassclass User:    id: int    username: str    email: str    hashed_password: strclass UserRepository:    def __init__(self):        self.users = {}        self.next_id = 1    def find_by_email(self, email: str):        for user in self.users.values():            if user.email == email:                return user        return None    def create(self, username, email, hashed_password):        user = User(            id=self.next_id,            username=username,            email=email,            hashed_password=hashed_password        )        self.users[self.next_id] = user        self.next_id += 1        return user
```

## 8. Create service.py

This is where business logic belongs.

```
from app.security import (    hash_password,    verify_password,    create_access_token)class AuthService:    def __init__(self, user_repository):        self.user_repository = user_repository    def register(self, username, email, password):        existing_user = self.user_repository.find_by_email(email)        if existing_user:            raise ValueError("Email already registered")        hashed_password = hash_password(password)        user = self.user_repository.create(            username,            email,            hashed_password        )        return user    def login(self, email, password):        user = self.user_repository.find_by_email(email)        if not user:            raise ValueError("Invalid email or password")
```

## 9. Create controller.py

Controller receives requests from the router and invokes the service.

```
from fastapi import HTTPException, statusfrom app.schemas import (    RegisterRequest,    LoginRequest,    UserResponse,    TokenResponse)class AuthController:    def __init__(self, auth_service):        self.auth_service = auth_service    def register(self, request: RegisterRequest):        try:            user = self.auth_service.register(                request.username,                request.email,                request.password            )            return UserResponse(                id=user.id,                username=user.username,                email=user.email            )        except ValueError as error:            raise HTTPException(                status_code=status.HTTP_409_CONFLICT,                detail=str(error)            )    def login(self, request: LoginRequest):        try:            token = self.auth_service.login(                request.email,                request.password            )            return TokenResponse(                access_token=token            )        except ValueError:            raise HTTPException(                status_code=status.HTTP_401_UNAUTHORIZED,                detail="Invalid email or password"            )
```

## 10. Create dependencies.py – Dependency Injection

This is the most important part of our implementation.

Instead of creating repository and service objects inside every controller method, FastAPI injects the required objects.

```
from app.repository import UserRepositoryfrom app.service import AuthServicefrom app.controller import AuthController# Shared repository instance for this demouser_repository = UserRepository()def get_user_repository():    return user_repositorydef get_auth_service():    repository = get_user_repository()    return AuthService(repository)def get_auth_controller():    service = get_auth_service()    return AuthController(service)
```

Observe the object creation sequence:

```
get_auth_controller()
        |
        v
AuthController
        |
        | receives
        v
AuthService
        |
        | receives
        v
UserRepository
```

This is Constructor Injection.

## 11. Create router.py

Router defines API endpoints and delegates the requests to the controller.

```
from fastapi import APIRouter, Depends, statusfrom app.controller import AuthControllerfrom app.dependencies import get_auth_controllerfrom app.schemas import (    RegisterRequest,    LoginRequest,    UserResponse,    TokenResponse)auth_router = APIRouter(    prefix="/auth",    tags=["Authentication"])@auth_router.post(    "/register",    response_model=UserResponse,    status_code=status.HTTP_201_CREATED)def register(    request: RegisterRequest,    controller: AuthController = Depends(get_auth_controller)):    return controller.register(request)@auth_router.post(    "/login",    response_model=TokenResponse)def login(    request: LoginRequest,    controller: AuthController = Depends(get_auth_controller)):    return controller.login(request)
```

## 14. Understand Dependency Injection practically

Let's compare two approaches.

Without Dependency Injection

```
def register(request):    repository = UserRepository()    service = AuthService(repository)    controller = AuthController(service)    return controller.register(request)
```

Problem: The application manually manages object creation and dependencies.

With Dependency Injection

```
def register(    request: RegisterRequest,    controller: AuthController = Depends(get_auth_controller)):    return controller.register(request)
```

FastAPI resolves the dependencies and supplies the controller.

## 16. Important production considerations

This is a teaching implementation, not yet production-ready.

| Area                | Production improvement                            |
| ------------------- | ------------------------------------------------- |
| Repository          | MySQL with SQLAlchemy                             |
| Password            | Argon2 hashing                                    |
| JWT                 | Secret from environment or secret manager         |
| Dependency lifetime | Request-scoped DB sessions                        |
| Concurrency         | Database transactions and unique email constraint |
| Authentication      | JWT validation and token expiry                   |
| Authorization       | Role-based access control                         |

The in-memory repository is shared only within this running process. It loses users on restart and is not suitable for multi-worker deployment.

## Mentor's final explanation

Remember this principle:

Dependency Injection is not just about using `Depends()`. It is about separating object creation from object usage.

```
              FastAPI
                 |
                 v
             Dependency
              Provider
                 |
          +------+------+
          |             |
          v             v
       Service      Repository
          |             |
          +------+------+
                 |
                 v
             Controller
                 |
                 v
               Router
```

The actual request execution starts at the Router and moves towards the Controller, Service and Repository. Dependency resolution supplies the required objects.

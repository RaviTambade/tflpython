# Encapsulation

Imagine an ATM. Can customers directly change the account balance inside the bank database? No. Everything goes through secure operations. This is

## Encapsulation

Hide data. Provide controlled access.

Example

```python
class BankAccount:

    def __init__(self):

        self.__balance=1000

    def deposit(self,amount):

        self.__balance+=amount

    def showBalance(self):

        print(self.__balance)
```

Usage

```python
account=BankAccount()

account.deposit(500)

account.showBalance()
```

The balance is protected from direct modification.

# Sample Implementation

```python
class Book:
    def __init__(self, book_id, title, author):
        self.book_id = book_id
        self.title = title
        self.author = author
        self.available = True

    def display(self):
        status = "Available" if self.available else "Issued"
        print(f"{self.book_id} | {self.title} | {self.author} | {status}")

    def issue(self):
        if self.available:
            self.available = False
            print(f'"{self.title}" issued successfully.')
        else:
            print("Book is already issued.")

    def return_book(self):
        self.available = True
        print(f'"{self.title}" returned successfully.')


class User:
    def __init__(self, user_id, name):
        self.user_id = user_id
        self.name = name

    def display(self):
        print(f"{self.user_id} - {self.name}")


class Member(User):
    def borrow_book(self, book):
        book.issue()

    def return_book(self, book):
        book.return_book()


class Librarian(User):
    def add_book(self, library, book):
        library.books.append(book)

    def remove_book(self, library, book_id):
        library.books = [b for b in library.books if b.book_id != book_id]


class Library:
    def __init__(self):
        self.books = []

    def display_books(self):
        print("\nLibrary Catalog")
        for book in self.books:
            book.display()


library = Library()

book1 = Book(101, "Python Programming", "Guido van Rossum")
book2 = Book(102, "Data Structures", "Narasimha Karumanchi")

library.books.extend([book1, book2])

member = Member(1, "Rahul")
librarian = Librarian(100, "Admin")

library.display_books()

member.borrow_book(book1)

library.display_books()

member.return_book(book1)

library.display_books()
```

# Applying the Four Pillars in the Project

| OOP Principle     | Example in Library System                                                                                                     |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **Encapsulation** | `Book` manages its availability through `issue()` and `return_book()` methods instead of exposing internal state directly.    |
| **Inheritance**   | `Member` and `Librarian` inherit common properties and behavior from `User`.                                                  |
| **Polymorphism**  | Different user types can provide their own implementation of library-related operations while sharing a common interface.     |
| **Abstraction**   | The `Library` class provides simple operations such as issuing or displaying books without exposing internal storage details. |

# Best Practices

* Model real-world entities as classes.
* Keep data private and expose it through methods when appropriate.
* Prefer composition or inheritance only when there is a clear relationship.
* Give each class a single responsibility.
* Design small, reusable methods with meaningful names.
* Follow naming conventions and document your classes and methods.

# Key Takeaways

* A **class** is a blueprint that defines the structure and behavior of objects.
* An **object** is an instance of a class with its own state and behavior.
* **Constructors (`__init__`)** initialize object data.
* **Encapsulation** protects data and provides controlled access.
* **Inheritance** promotes code reuse by extending existing classes.
* **Polymorphism** allows the same interface to produce different behaviors.
* **Abstraction** hides implementation details and exposes only essential functionality.
* OOP enables developers to build modular, maintainable, scalable, and industry-ready software systems.

# 2. First Principle: What is a Process?

A **process** is a running instance of a program.

For example:

```text
insurance.py
     │
     ▼
  PROCESS
     │
     ├── Memory
     ├── Variables
     ├── Python runtime
     └── Execution
```

Suppose we start two Python programs:

```text
Process A
   │
   ├── Memory A
   └── Code A

Process B
   │
   ├── Memory B
   └── Code B
```

They have **separate memory spaces**.

That isolation is important.

# 3. What is a Thread?

A process can contain multiple threads.

```text
PROCESS
│
├── Thread 1
├── Thread 2
├── Thread 3
└── Thread 4
```

Threads belong to the same process and can share process memory.

Think about an office.

```text
             COMPANY
                │
             PROCESS
                │
      ┌─────────┼─────────┐
      │         │         │
   Employee   Employee   Employee
   Thread 1   Thread 2   Thread 3
```

They are working inside the same organization and can access common resources.

# 4. Multithreading

**Multithreading = multiple threads executing within one process.**

Python provides:

```python
import threading
```

Simple example:

```python
import threading
import time

def download_policy():
    print("Downloading policy...")
    time.sleep(3)
    print("Policy downloaded")

def send_email():
    print("Sending email...")
    time.sleep(2)
    print("Email sent")

t1 = threading.Thread(target=download_policy)
t2 = threading.Thread(target=send_email)

t1.start()
t2.start()

t1.join()
t2.join()

print("All tasks completed")
```

Instead of:

```text
Download
   ↓
wait 3 sec
   ↓
Email
   ↓
wait 2 sec
```

we can have:

```text
Thread 1: Download ────────────────┐
                                   │
Thread 2: Email ─────────────┐     │
                             │     │
                             ▼     ▼
                         Completed
```

### Mentor Question

**Why does this help?**

Because while one thread is **waiting for I/O**, another thread can perform useful work.

# 5. Important Python Concept: GIL

Now comes the famous Python question:

> **“Sir, if Python has multiple threads, can they execute Python code in parallel on multiple CPU cores?”**

For **CPython**, the traditional answer is:

> The **Global Interpreter Lock (GIL)** allows only one thread at a time to execute Python bytecode within a process.

Therefore, threads are generally not the solution for **CPU-bound Python code**.

But this does **not** mean threads are useless.

They are very useful for **I/O-bound workloads**.

For example:

```text
Database request
       ↓
     WAIT
       ↓
API request
       ↓
     WAIT
       ↓
File operation
       ↓
     WAIT
```

During waiting, another thread can make progress.

# 8. Multiprocessing

Now Ravi Sir asks:

> “If one Python process cannot efficiently execute CPU-bound Python code concurrently because of the GIL, what can we do?”

Student:

> “Create multiple processes!”

Exactly.

```text
             APPLICATION
                  │
       ┌──────────┼──────────┐
       │          │          │
       ▼          ▼          ▼
   Process 1  Process 2  Process 3
       │          │          │
      CPU1       CPU2       CPU3
```

Example:

```python
from multiprocessing import Process

def calculate():
    total = 0

    for i in range(10_000_000):
        total += i

    print(total)

p1 = Process(target=calculate)
p2 = Process(target=calculate)

p1.start()
p2.start()

p1.join()
p2.join()

print("Completed")
```

Here, we create separate processes.

Each process has its own Python interpreter/runtime and memory space.


# 9. Thread vs Process

This is an important interview question.

```text
THREAD
──────────────────────

Process
│
├── Thread 1
├── Thread 2
└── Thread 3

Shared process memory
```

versus:

```text
PROCESS
──────────────────────

Process 1
   │
   └── Memory 1

Process 2
   │
   └── Memory 2

Process 3
   │
   └── Memory 3
```

### Conceptual comparison

| Feature               | Thread                           | Process                        |
| --------------------- | -------------------------------- | ------------------------------ |
| Memory                | Shared within process            | Separate                       |
| Creation cost         | Usually lower                    | Usually higher                 |
| Communication         | Easier but needs synchronization | Requires IPC/shared mechanisms |
| Isolation             | Lower                            | Higher                         |
| I/O-bound             | Good                             | Possible                       |
| CPU-bound Python code | Often limited by GIL             | Good fit                       |
| Failure isolation     | Lower                            | Higher                         |


# 10. The Third Model: Async Programming

Now we introduce:

```python
asyncio
```

Ravi Sir asks:

> “Do we always need multiple threads to handle many I/O requests?”

No.

Python can use **asynchronous programming**.

The basic idea:

> **Don't block while waiting for I/O.**

Example:

```python
import asyncio

async def download_policy():
    print("Downloading...")
    await asyncio.sleep(3)
    print("Downloaded")

async def send_email():
    print("Sending email...")
    await asyncio.sleep(2)
    print("Email sent")

async def main():
    await asyncio.gather(
        download_policy(),
        send_email()
    )

asyncio.run(main())
```

Conceptually:

```text
                 EVENT LOOP
                     │
          ┌──────────┴──────────┐
          │                     │
      download()             email()
          │                     │
       await                 await
          │                     │
       waiting               waiting
          │                     │
          └─────────┬───────────┘
                    │
                 Event Loop
```

The event loop can move to another task while one task is waiting.


# 11. What Does `async` Mean?

When we write:

```python
async def get_policy():
    ...
```

we are defining a **coroutine function**.

And:

```python
await get_policy()
```

means:

> “Run this asynchronous operation and allow the event loop to handle other work while this operation is waiting.”

The keyword:

```python
await
```

is extremely important.


# 12. What is an Event Loop?

Think of an event loop as a smart coordinator.

```text
             EVENT LOOP
                 │
       ┌─────────┼─────────┐
       │         │         │
       ▼         ▼         ▼
    Task A     Task B    Task C
       │         │         │
     WAIT      READY     WAIT
                 │
                 ▼
              Execute
                 │
                 ▼
             Task B done
```

Instead of creating one thread for every operation, the event loop coordinates many asynchronous tasks.

# 16. Thread Pool

Creating threads manually isn't always necessary.

Python provides:

```python
from concurrent.futures import ThreadPoolExecutor
```

Example:

```python
from concurrent.futures import ThreadPoolExecutor

def download(policy_id):
    print("Downloading policy", policy_id)
    return policy_id

policy_ids = [101, 102, 103, 104]

with ThreadPoolExecutor(max_workers=4) as executor:
    results = executor.map(download, policy_ids)

print(list(results))
```

Conceptually:

```text
             Thread Pool
        ┌──────┬──────┬──────┐
        │ T1   │ T2   │ T3   │ T4
        └──────┴──────┴──────┘
             ▲
             │
           Tasks
```

The pool manages worker threads for us.

# 17. Process Pool

Similarly:

```python
from concurrent.futures import ProcessPoolExecutor

def calculate(n):
    return n * n

numbers = [10, 20, 30, 40]

    results = executor.map(calculate, numbers)

print(list(results))
```

Conceptually:

```text
             Process Pool
        ┌────────┬────────┬────────┐
        │   P1   │   P2   │   P3   │
        └────────┴────────┴────────┘
             ▲
             │
          CPU tasks
```

# 18. Synchronization Problem

Now Ravi Sir introduces the next problem.

Two threads modify the same variable:

```python
balance = 1000
```

Thread 1:

```text
Withdraw ₹700
```

Thread 2:

```text
Withdraw ₹500
```

Both read:

```text
balance = 1000
```

Potentially:

```text
Thread 1 → read 1000
Thread 2 → read 1000

Thread 1 → write 300
Thread 2 → write 500
```

Final balance:

```text
500
```

But expected business behavior should reject one withdrawal.

This is a **concurrency/shared-state problem**.

# 19. Lock

Python provides synchronization primitives such as:

```python
threading.Lock
```

Example:

```python
import threading

lock = threading.Lock()

balance = 1000

def withdraw(amount):
    global balance

    with lock:
        if balance >= amount:
            balance -= amount
            print("Withdrawal successful")
        else:
            print("Insufficient balance")
```

The lock protects the critical section.

```text
Thread 1
   │
   ▼
[ LOCK ]
   │
   ▼
modify balance
   │
   ▼
[ UNLOCK ]
```

# 20. Race Condition

A **race condition** occurs when the result depends on the timing/interleaving of concurrent operations.

Classic example:

```text
Thread A ── read ── calculate ── write
Thread B ───── read ── calculate ── write
```

The operations race with each other.

Mentor lesson:

> **Concurrency creates opportunities for performance—but also creates synchronization problems.**

# 21. Deadlock

Another important concept.

Imagine:

```text
Thread A owns Lock 1
       │
       └── waiting for Lock 2

Thread B owns Lock 2
       │
       └── waiting for Lock 1
```

Nobody can continue.

```text
      Lock 1
       ▲  │
       │  ▼
Thread A   Thread B
       ▲  │
       │  ▼
      Lock 2
```

This is a **deadlock**.

# 23. Interview Questions for Python Developers

### Q1. What is a process?

A running instance of a program with its own memory space and execution resources.

### Q2. What is a thread?

A unit of execution within a process that shares the process's resources.

### Q3. When would you use multithreading?

Typically for I/O-bound work, especially when using blocking APIs.

### Q4. When would you use multiprocessing?

For CPU-intensive Python workloads where process-level parallelism is useful.

### Q5. What is `asyncio`?

Python's asynchronous I/O framework based around an event loop and coroutines.

### Q6. What does `await` do?

It suspends the current coroutine until the awaited operation can continue, allowing the event loop to run other ready tasks.

### Q7. Does async make CPU-intensive code faster?

Generally **no**. Async primarily helps with concurrency for operations that spend time waiting, especially I/O.

### Q8. Does multithreading always mean parallel execution?

No. Concurrency and parallelism are different concepts, and CPython's GIL historically limits simultaneous execution of Python bytecode by threads.
